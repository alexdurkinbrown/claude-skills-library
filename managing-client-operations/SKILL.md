# Section A — Client Onboarding Package

## Inputs
Company/product name, who is being onboarded (client/employee/user), primary goal of onboarding, timeline (7/30/90-day), tools/platforms they'll use, any existing materials.

## Deliverables

### Welcome Email Sequence (7 emails)
Day 0: Warm welcome + single CTA / Day 1: First quick win / Day 3: Key feature or value spotlight / Day 5: Social proof or success story / Day 7: Check-in + support offer / Day 14: Milestone celebration / Day 21: Expansion CTA.
Per email: subject, preview text, body <200 words, CTA.

### First-Week Task Checklist (Sheets)
| Day | Task | Owner | Time Estimate | Resource/Link | Done ✓ |
Day-by-day with client vs. your team ownership clearly marked.

### Training Outline
Module-by-module: learning objectives, delivery method (video/doc/live/self-serve), estimated time, assessment step.

### Quick-Start Reference Pack
- 1-page quick-start guide
- FAQ doc (top 10 Q&A)
- Escalation path (who to contact for what)

### Onboarding Success Metrics
3 activation milestones (Day 1 / Day 7 / Day 30), leading indicators, at-risk red flags, dashboard structure for tracking cohort progress.

# Section B — Meeting Transcript Processing

## Inputs
Meeting transcript (file or pasted text). Optional: meeting type, participant list.

## Process
1. Identify speakers, roles, date, purpose
2. Extract every action item: task, owner, deadline, priority, source quote from transcript
3. Document every decision made: statement, approver, conditions, downstream impact
4. Write meeting minutes: title + attendees + 3–5 sentence summary + discussion topics + decisions + action items + next meeting

## Deliverables

### Action Item Tracker (Sheets-ready)
| # | Action Item | Owner | Deadline | Priority | Status | Source Quote |
Status defaults to "Open". Flag any item missing an owner or deadline.

### Meeting Minutes (export-ready)
Professional format, neutral tone, <600 words unless complex.

### Personalized Follow-Up Emails (one per participant)
Reference specific things they said or committed to. List only their action items. Include decisions affecting them. Subject line + body <200 words. Ready to send.

# Section C — File Organization

## Inputs
Current folder structure (describe or share), types of files involved, team size, how files are accessed, naming pain points.

## Deliverables
- Recommended folder hierarchy (depth max 3 levels)
- File naming convention (format: [Date]-[Project]-[Type]-[Version])
- Migration plan: current state → target state, which files move where
- Archiving rules: when to archive, where to put archived files
- Quick-reference guide for the team (1 page)

# Section D — Spreadsheet & Data Analysis

## Inputs
Spreadsheet or data file (upload), analysis goal (what decision does this need to inform?), any context about what the data represents.

## Process
1. Audit data quality: duplicates, blanks, format inconsistencies — flag and clean
2. Identify the 3–5 most meaningful patterns or insights in the data
3. Run relevant calculations (totals, averages, growth rates, ratios, rankings)
4. Build summary view: key metrics at a glance
5. Apply appropriate visualization structure (which chart type fits which insight)

## Deliverables
- Clean dataset (corrected formatting, deduped)
- Insight summary: top 3–5 findings with plain-language interpretation
- Recommended actions based on findings
- Dashboard structure (Sheets): KPIs, chart types, filters, data sources
- If financial data: trend analysis, anomaly flags, projection model
