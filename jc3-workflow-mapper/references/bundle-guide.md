# Bundle Guide

## Purpose

When a user has documented multiple workflows using Workflow Mapper (each as a standalone file), they may want to combine them into one unified workflow system file. This guide handles that consolidation.

## When to Use This Guide

Use this guide only when:
1. The user has 2 or more standalone workflow files from previous Workflow Mapper sessions
2. They explicitly say they want to bundle them
3. You are at Phase 8 of the session flow and have finished the primary workflow

Do NOT use this guide proactively. Offer the bundle option once, at the end of the session, only if the user has multiple workflow files. Honor their choice.

## What Bundling Produces

Bundling takes multiple standalone workflow files and combines them into one file called `my-workflow-system.md`. The bundled file includes:

1. A table of contents at the top listing all workflows
2. Each workflow as its own section, preserving the exact structure from the standalone file
3. Cross-reference notes between workflows where relevant
4. A unified frontmatter that covers the full set

The original standalone files are NOT deleted. Bundling is a consolidation for convenience, not a replacement. The user can keep using the standalone files, or switch to the bundled file, or both.

## How to Bundle

### Step 1: Gather the workflow files

Ask the user:

"How many workflow files do you have? Tell me the names. They should look like:
- content-production-workflow.md
- client-delivery-workflow.md
- launch-sequence-workflow.md

Paste the contents of each one, or upload them. I will combine them into one file."

Wait for them to provide all the files.

### Step 2: Confirm the scope

"Got it. I will bundle [N] workflows:
- [Workflow name 1]
- [Workflow name 2]
- [Workflow name 3]

The new file will be called `my-workflow-system.md`. Your standalone files will still work. This is a consolidation for convenience.

Good to proceed?"

Wait for confirmation.

### Step 3: Generate the bundled file

Use this structure:

```markdown
---
name: my-workflow-system
description: Unified workflow operating system for [BUSINESS NAME]. This file contains multiple documented workflows that AI can execute with full context. Reference this file whenever running any of the workflows documented below. Each workflow has its own triggers, steps, decision points, and edge cases. Apply voice rules from my-brand-voice.md at all AI-producing steps if that file exists. Pair with my-creator-ai-system.md for business context.
---

# Workflow System . [BUSINESS NAME]

This file bundles multiple workflows into one reference. Each workflow below is a complete operational unit. When AI is asked to handle any specific workflow, it should reference only the matching section.

## Workflows in This System

- [Workflow Name 1] . Last updated [DATE]
- [Workflow Name 2] . Last updated [DATE]
- [Workflow Name 3] . Last updated [DATE]

## Companion Files

- `my-creator-ai-system.md` . Business context from the Creator AI Scorecard
- `my-brand-voice.md` . Voice architecture from Voice Builder (if generated)

---

[INSERT FULL CONTENT OF WORKFLOW 1 FILE HERE, starting from the # Workflow line. Remove its frontmatter since the bundled file has its own.]

---

[INSERT FULL CONTENT OF WORKFLOW 2 FILE HERE, same treatment]

---

[INSERT FULL CONTENT OF WORKFLOW N FILE HERE, same treatment]

---

*Generated by bundling [N] workflow files via the Creator AI Skills Stack.*
```

### Step 4: Preserve the standalone structure of each workflow

When combining files:

- Keep the full workflow content intact (Purpose, Trigger, Steps, Decision Points, Edge Cases, AI Integration Notes, Revision Notes)
- Do NOT reformat or reorganize individual workflow sections
- Do NOT try to deduplicate similar steps across workflows
- Do NOT add editorial commentary between workflows
- Use `---` as the separator between workflow sections

### Step 5: Deliver the bundled file

"Your workflow system is bundled.

**File: `my-workflow-system.md`**

This contains all [N] workflows in one reference. Your original standalone files are still on your system and still work.

Here is how to use the bundle:

**Upload to a Claude Project.** All your workflows in one file. Claude has access to the full system when you work in that project.

**Keep the standalone files too.** If you prefer to load individual workflows for specific projects, the standalone files still work for that. Use whichever fits the context.

**Update the bundle when workflows change.** When you update a standalone workflow file, come back and re-bundle. The bundle is a snapshot, not a live system."

## Rules for Bundling

### Do NOT bundle more than 5 workflows in one file

If the user has more than 5 workflow files, the bundle becomes unwieldy. Recommend splitting:

"You have [N] workflow files. At that scale, one bundled file gets hard to work with. Better move: create themed bundles. Group by function. Example:

- `content-system.md` (content-related workflows)
- `delivery-system.md` (client/customer workflows)
- `ops-system.md` (internal workflows)

Pick the grouping that matches how you actually reference these. Bundle by theme, not alphabetically."

### Do NOT bundle workflows that do not exist

If the user claims to have files they cannot produce: "I need the actual file contents to bundle. If the file exists, paste it. If you just remember making it but can't find it, we may need to recreate it."

### Do NOT modify individual workflow content

Bundling combines. It does not rewrite. If the user wants to update a workflow, that is a separate session (re-run Workflow Mapper for that workflow).

### Keep the bundle file name generic

The bundled file is always named `my-workflow-system.md`. This is intentional. The standalone files use specific names (e.g., `content-production-workflow.md`). The bundle uses the generic name to signal "this is the combined system."

## When Bundling Makes Sense

Bundling is worth doing when:
- User has 2-5 workflow files
- They use all of them in the same Claude Project
- They are tired of uploading multiple files

Bundling is NOT worth doing when:
- User only has 1 workflow
- User keeps their workflows in different Projects
- User is doing this preemptively "just in case"

If the user is unsure whether to bundle, ask: "How often do you load multiple workflow files into the same Claude conversation? If rarely, keep them standalone. If always, bundling saves you time."

## After Bundling

Close cleanly:

"Bundle delivered. If you update any workflow later, come back and re-bundle. Workflow Mapper generates the standalone files. This guide handles the consolidation whenever you want it."

Do not pitch anything. The session is complete.
