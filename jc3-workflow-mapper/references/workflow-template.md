# Workflow Output Template

## Purpose

This file defines the structure of the standalone workflow markdown file that the skill generates. Each session produces ONE file named after the workflow.

## Generation Instructions

### 1. Fill in every bracketed field with specifics from the session

Generic placeholders are worse than useless. Every field should contain information the user provided during the interview. If they did not cover a field, go back and ask before writing the section.

### 2. Write for AI, not for humans

The workflow file is operational context for AI execution. It should NOT read like a human-facing SOP. Signs you are writing for humans instead of AI:

- Prose descriptions instead of structured fields
- "Why" explanations instead of "what" specifics
- Context about the business or industry (that belongs in the Creator AI file)
- Motivational or aspirational language

### 3. The "AI role" field for each step is critical

Use one of three values:

- **NONE:** AI does not participate in this step. Human-only action.
- **ASSIST:** AI helps a human complete this step (e.g., drafts content the human reviews).
- **EXECUTE:** AI can complete this step autonomously given the input.

For ASSIST and EXECUTE steps, specify what prompt or context AI needs. Example:

> **AI role:** ASSIST . "Given the topic and target audience, produce a draft headline. Apply voice rules from my-brand-voice.md. Offer 3 variations. Human selects or edits."

### 4. Edge cases should have specific AI responses

Do not write "AI should use judgment." AI will use judgment poorly when the workflow does not define good responses. Be specific:

- **STOP AND ESCALATE:** AI halts and notifies the user. Use for unclear situations where human judgment is essential.
- **TRY ALTERNATIVE:** AI attempts a specific fallback the workflow defines. Use for known-but-rare situations with a standard workaround.
- **DEFER TO USER:** AI presents the situation to the user and asks for direction. Use for cases where a decision is needed but not obvious.

### 5. File naming

Name the file after the workflow in kebab-case with `-workflow` appended:

- "Content Production" → `content-production-workflow.md`
- "Client Delivery" → `client-delivery-workflow.md`
- "Weekly Newsletter" → `weekly-newsletter-workflow.md`
- "Product Launch" → `product-launch-workflow.md`

Do NOT use generic names like `workflow.md` or `my-workflow.md`. The workflow name is the filename.

### 6. One file, standalone

The file should be complete on its own. No external references except to `my-brand-voice.md` and `my-creator-ai-system.md` (companion files from other Skills Stack skills). Do not reference other workflow files.

If the user later wants to bundle multiple workflow files into one system, that is handled separately by `references/bundle-guide.md`. Do not try to pre-structure for that at generation time.

## What This File Does NOT Include

Keep these OUT of the workflow file:

- Marketing copy about the workflow
- Why this workflow matters to the business
- How the workflow evolved over time (unless brief in Revision Notes)
- Advice or best practices (the workflow documents YOUR way, not THE way)
- Links to external resources (put those in my-creator-ai-system.md if needed)
- Jim's contact info or product pitches

If the user asks to include strategic context, explain: "That belongs in the Creator AI file, not the workflow file. This file is operational only. Keeping it tight means AI executes faster and cleaner."
